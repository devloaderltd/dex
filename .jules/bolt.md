## 2026-04-13 - Cache external loop static calls across beacon proxy pair loops
**Learning:** In the PurDex architecture, AMM pair addresses cannot be computed locally via CREATE2 hash because they are deployed as `BeaconProxy` instances. Resolving pair addresses requires an external call to `IPurDexFactory.getPair()`. When looping over multi-hop routing paths, passing the initially resolved pair into the loop and caching the `to` address for the next iteration removes redundant cross-contract lookups.
**Action:** When iterating over multi-hop AMM logic, remember that PurDex pairs are BeaconProxies. Always pass the resolved address from the caller or cache the resolved `to` address in a local variable to serve as the `currentPair` for subsequent loop iterations to avoid redundant factory calls.
