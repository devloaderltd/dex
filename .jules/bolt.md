## 2026-06-30 - Optimize Staking Rewards updateReward & exit functions
**Learning:** Calling `earned()` within the `updateReward` modifier of standard Synthetix-style staking contracts redundantly recalculates `rewardPerToken()`, which is already computed and stored earlier in the same modifier. Additionally, composite functions like `exit()` that sequentially call other public/external state-modifying functions (e.g., `withdraw()` and `getReward()`) incur redundant modifier executions (such as `updateReward` and `nonReentrant`), inflating gas costs.
**Action:** Inline the `earned()` logic using `rewardPerTokenStored` inside the `updateReward` modifier. Refactor external-facing functions called by composite functions to use internal `_withdraw` and `_getReward` helpers, enabling the composite function to apply modifiers once and call the internal helpers directly, saving gas on multiple modifier executions.
