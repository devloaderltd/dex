## 2024-05-30 - Redundant Modifier & Getter Execution in Staking Rewards
**Learning:** In composite functions like `exit()` that call multiple external-facing state-changing functions (e.g., `withdraw()` and `getReward()`), modifiers like `nonReentrant` and `updateReward` are executed redundantly. Furthermore, calling view functions like `earned()` inside `updateReward()` which then call `rewardPerToken()` recalculates values that are already cached in state variables (like `rewardPerTokenStored`).
**Action:** Always extract core logic into internal helpers (e.g., `_withdraw`, `_getReward`) and have the composite functions call those directly, applying the modifiers just once on the composite entry point. Also, inline calculations inside modifiers to reuse newly updated state variables instead of triggering full external view function calculations.
