## 2024-05-24 - Avoid redundant external calls to compute pair address
**Learning:** In PurDex, AMM pairs use `BeaconProxy` instances, preventing the use of local `CREATE2` hash logic to compute addresses. This means `IPurDexFactory(factory).getPair()` must be called to fetch a pair's address, resulting in an external call. Calling this multiple times per swap hop is a noticeable performance bottleneck due to the added gas costs of external calls vs local memory tracking.
**Action:** When performing multi-hop loops (like in `_swap`), fetch the initial pair address before entering the loop, pass it as a parameter, and then update it with the next pair's address at the end of each loop iteration. This avoids redundantly querying the factory for the current pair on every hop.
