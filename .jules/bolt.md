## 2026-05-16 - Router Multi-hop Swap Optimization
**Learning:** In multi-hop swaps (where `path.length > 2`), `_swap` iteratively computes the pair address for `(input, output)` as well as the pair address for `(output, path[i+2])` (which is the input and output for the next iteration). This implies redundancy: calculating `IPurDexFactory(factory).getPair(output, path[i + 2])` computes the exact same address that `IPurDexFactory(factory).getPair(input, output)` will compute in the next loop iteration. This can be optimized using a sliding window cache where `currentPair` starts as the first pair and the next pair is precomputed if needed, then assigned to `currentPair` for the next round.
